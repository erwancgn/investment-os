## Résidus d’infrastructure transversaux

| Occurrence | Classe | Conclusion |
|---|---|---|
| Notion direct, noms physiques de bases/propriétés, relations ou D1 dans les tool plans actifs | **Supprimée / remplacée par MCP-Core** | Aucun plan MCP actif ne lit ou n’écrit directement ces éléments. `get_company`, Current, Portfolio/Position, Quote et `save_analysis` délèguent au serveur/Core/adapters. |
| Résolution manuelle d’identité, alias/ticker→ID dans les Skills | **Supprimée / remplacée par `resolve_company`** | L’identité est résolue une fois; aucun mapping portefeuille/watchlist codé en dur. |
| Sélection Current, fallback « dernière analyse », relation Company↔Analysis | **Remplacée par Core-MCP** | Les Skills appellent Current par famille ou hydratent une archive identifiée. Aucun tri local ni reconstruction de relations. |
| Write direct, retry infrastructurel de mutation, receipts simulés | **Supprimée / interdite** | Seul `save_analysis` peut persister dans un runtime explicitement autorisé; pas de retry automatique. En production READ-only, `NOT_REQUIRED`. |
| Détails providers historiques Setup et compatibilité d’affichage Notion | **Légitimes sous choix explicite** | Ces contenus ne définissent pas le chemin MCP et aucun fallback ne les déclenche après forbidden, erreur ou timeout. |
| Phrase Company absente/cold start et création historique dans certains préflights | **Ambiguïté bornée** | En MCP Lot 12, `not_found` ne crée rien. Les mentions historiques sont explicites au profil Setup, mais la formulation demeure à harmoniser ultérieurement si le chemin historique est supprimé. |
| Neuf copies de la référence MCP commune | **Dette documentaire** | Elles sont actuellement byte-identiques et vérifiées par test; leur déduplication exige une évolution de packaging/routage hors de ce lot. |
| Modèles de portfolio et validation fraîcheur Quote | **Légitime, méthode** | Les calculs demeurent dans les frameworks; ils ne constituent pas une reconstruction des index backend ni un normaliseur physique local. |

## Gate de complétude / méthodes

Dans la copie 1.3.8, les huit contrats d’exécution identiques et les deux Skills composites exigent un rendu intégral selon chaque framework, toutes ses sections, Evidence Ledger/Evidence Gate complets et handoffs réellement produits. Les méthodes, scores, seuils et critères financiers n’ont pas été modifiés.
